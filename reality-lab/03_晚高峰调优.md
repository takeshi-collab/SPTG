## 1. 老挝 5G 晚高峰 (20:00 - 23:00 Lao) 网络特征分析

1. **无线基站拥塞 (Radio Air Interface Congestion)**：老挝 5G 无线基站（Lao Telecom / Unitel 等）在晚高峰时段由于接入终端激增，信道资源紧张，导致丢包率上升 (3%~15%)，RTT 抖动剧烈 (80ms ~ 300ms)。
2. **运营商 CGNAT / QoS 限速**：
   - **UDP 深度包检测与 QoS 压制**：老挝运营商普遍对 UDP 流量（如 Hysteria2, QUIC, WireGuard）施加单线程限速或随机丢包。
   - **TCP 长连接限制**：并发 TCP 连接数过多或单连接持续高吞吐时，CGNAT 网关容易丢弃 SYN 或强制断连。
3. **国际出口带宽瓶颈**：老挝至泰国/香港/新加坡的陆缆/海底光缆出境节点在晚高峰容易拥塞。

## 2. 核心调优维度与参数配置指南

### 2.1 拥塞控制算法：BBR vs BRUTAL vs Cubic
- **TCP BBR (推荐于 TCP 链路)**：Linux 内核默认开启 BBR。BBR 能有效抗 5%~10% 的随机丢包，在丢包下维持平稳吞吐。
- **BRUTAL (仅适用于 Hysteria2 UDP)**：激进的发包算法。若丢包率高但上行未被运营商 UDP QoS 杀掉，BRUTAL 能硬抗 20%+ 丢包；但若运营商压制 UDP，BRUTAL 会加速被封禁或丢包率飙升至 50%+。

**Hub 节点 BBR 优化命令 (Debian)**：
```bash
# 启用 BBR + fq 队列
sysctl -w net.core.default_qdisc=fq
sysctl -w net.ipv4.tcp_congestion_control=bbr
echo "net.core.default_qdisc=fq" >> /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" >> /etc/sysctl.conf
sysctl -p
```

### 2.2 端口策略 (Port Selection Strategy)
- **TCP 443 (现状：使用中)**：**最优伪装**。跨国 443 端口在 CGNAT 和 GFW 中享有最高优先级，且不容易被运营商 QoS 压制。
- **UDP 443 (QUIC / Hysteria2)**：晚高峰容易被老挝运营商降级为低优先级 QoS。
- **高位随机端口 (e.g., TCP/UDP 20000-60000)**：用于备用链路（WireGuard / Hysteria2 端口跳变）。

### 2.3 sing-box Mux (Multiplexing 多路复用)
- **原理**：在单条 TCP 隧道中并发复用多个代理请求，减少 TCP 三次握手和 TLS 1.3 握手延迟（晚高峰节约 150ms~300ms 握手时间）。
- **客户端配置片段 (sing-box config.json)**：
  ```json
  "outbounds": [
    {
      "type": "vless",
      "tag": "reality-out",
      "server": "<HUB_IP>",
      "server_port": 443,
      "multiplex": {
        "enabled": true,
        "protocol": "h2mux",
        "max_connections": 4,
        "min_streams": 4,
        "padding": true
      }
    }
  ]
  ```

## 3. “症状 ➔ 动作” 调优决策树 (用户对号入座)

```
[晚高峰使用场景出现异常]
       │
       ├─► 现象 1：网页加载首包极慢（握手等待），但下载速度正常
       │      └─► 方案：开启 sing-box client 端的 `multiplex` (h2mux，并发 4 条连接)
       │
       ├─► 现象 2：视频/大文件下载卡顿，ping 延迟剧烈抖动且丢包率 > 8%
       │      └─► 方案 A：在 GCP Hub 开启 TCP BBR + fq
       │      └─► 方案 B：切换至 IPv6 出口 B（绕过 IPv4 CGNAT 拥塞）
       │
       ├─► 现象 3：UDP 协议 (如 Hysteria2/QUIC) 速度瞬间归零或断连
       │      └─► 原因：老挝 5G 运营商开启晚高峰 UDP QoS 截流
       │      └─► 方案：切回 TCP 443 (VLESS-Reality)；停用 UDP 直连
       │
       └─► 现象 4：所有网页打不开，出现 TCP 连接超时 (Connection Timeout)
              └─► 原因：出口 A (Rola 10M 住宅 IP) 或 GCP Hub 遭遇死锁
              └─► 方案：触发主备自动切换至备用节点 (见 08_主备自动切换.md)
```

## 4. 优化总结与建议

- **当前配置 (VLESS-Reality TCP 443) 已是晚高峰抗 QoS 能力最强的组合**。
- **建议增量改动**：
  1. 确认 GCP Hub VM 的 Linux 内核已加载 `bbr` 与 `fq`。
  2. 在 OpenWrt 客户端的 sing-box 配置中为 VLESS outbound 启用 `multiplex` (h2mux)，优化多并发小包（网页/AI 对话）体验。
