# 05. 流量监控与可视化方案评估与部署要点

**状态**：结论明确，给出“不增加攻击面”推荐方案与部署指南

---

## 1. 核心需求与约束

- **需求**：对代理链路的流量（如累计流量、连接数、节点状态、SOCKS5 出口可用性）进行可视化监控。
- **核心约束**：**严禁增加公网攻击面**（不公开 Web UI 到公网，不上暴露鉴权漏洞的第三方 Web 面板），且需保持 GCP Hub 轻量稳定（极低 CPU/内存开销）。

---

## 2. 候选方案对比分析

| 方案 | 架构描述 | 优点 | 缺点/安全隐患 | 推荐指数 |
|---|---|---|---|---|
| **方案 1：3x-ui 面板** (Xray/sing-box UI) | 独立 Go Web 服务，自带 sqlite 数据库与网页控制台 | 界面功能丰富，支持在线管理节点与用户流量 | 占用额外的 Web 端口（80/443/2053 等），历史上**多次爆发未授权 RCE / SQL 注入漏洞**；增加暴露面 | 🔴 **不推荐** (严重违反“不增攻击面”军规) |
| **方案 2：sing-box REST API + Clash Web Dashboard (仅绑 Loopback / Local Unix Domain Socket)** | 利用 sing-box 原生 `experimental.clash_api` 暴露 REST 接口，配合本地静态 HTML 控制台 | **原生无额外进程**，性能开销几乎为零；可直接通过 SSH 隧道或仅绑 `127.0.0.1:9090` | 需要手动开启 API，前端需要通过 SSH Tunnel 访问 | 🟢 **强烈推荐** (兼顾安全与可视) |
| **方案 3：Prometheus + Grafana 监控栈** | 导出 sing-box / systemd / node_exporter 指标 | 极为专业，监控指标详尽 | 占用较多 RAM (200M+) 和 CPU，部署维护复杂 | 🟡 适合多节点大规模集群，个人 Hub 过重 |
| **方案 4：vnStat 命令行 / 终端 UI** | 系统级网卡流量统计工具 (`vnstat` / `vnstati`) | 极其轻量，零公网监听端口 | 仅网卡级流量，无法按 SOCKS5 出口或域名细分 | 🟢 **推荐作为本地 CLI 补充** |

---

## 3. 推荐方案落地指南：sing-box REST API + 安全访问

### 3.1 步骤 1：在 GCP Hub `sing-box` 中开启 REST API
在 GCP Hub 的 `/etc/sing-box/config.json` 顶部加入 `experimental` 配置：

```json
{
  "experimental": {
    "clash_api": {
      "external_controller": "127.0.0.1:9090",
      "external_ui": "ui",
      "secret": "<GENERATE_RANDOM_SECRET>",
      "default_mode": "rule"
    }
  }
}
```
*注：`external_controller` 仅绑定 `127.0.0.1`，拒绝公网直连！*

### 3.2 步骤 2：安全访问 Dashboard (通过 IAP / SSH 隧道)

本地执行体（或用户 Mac/PC）需要查看面板时，只需拉起一条 SSH 隧道将控制台端口映射至本地：

```bash
# 通过 IAP 建立本地 9090 端口映射
gcloud compute start-iap-tunnel usa-hub-1 9090 \
    --local-host-port=127.0.0.1:9090 \
    --zone=us-west1-a
```

然后本地浏览器打开：`http://127.0.0.1:9090/ui` 即可查看图形化流量仪表盘（包含实时吞吐、活跃 TCP 连接数、节点延迟分布）。

### 3.3 步骤 3：轻量命令行统计 (vnStat) 部署
在 Hub 上安装 `vnstat` 查看每日/每月网卡汇总流量：

```bash
sudo apt-get update && sudo apt-get install -y vnstat
sudo systemctl enable --now vnstat

# 常用命令
vnstat -i eth0 -d   # 按天查看流量
vnstat -i eth0 -m   # 按月查看流量
vnstat -i eth0 -l   # 实时流量监控
```

---

## 4. 总结

1. **坚决放弃 3x-ui / v2ray-ui 等外置 Web 面板**，彻底切断面板暴露带来的黑客扫频与 0-day 漏洞风险。
2. **采用 sing-box 原生 `clash_api` 绑定 `127.0.0.1` + SSH / IAP Tunnel 映射**，实现“零攻击面暴露”的流量可视化。
