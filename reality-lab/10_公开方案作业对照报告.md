# 10. 公开社区开源方案作业对照与差距分析报告

**状态**：结论明确，附与四大公开来源的深度对照表格与差距补救分析

---

## 1. 参照来源概述 (作业核验)

依据任务包提供的社区作业素材，对照现行部署（`usa-hub-1` + OpenWrt sing-box TUN + Rola SOCKS5），进行逐项比对：

1. **来源 A (`gcp-free-tier-proxy`)**：GCP 免费层/低成本 VM 上的 sing-box 部署工具包 (包含 egress-guard 流量计费守护、IAP SSH 管理面收宽、端口策略)。
2. **来源 B (`sing-box` 官方文档)**：VLESS / Reality / TUN 官方规范。
3. **来源 C (`go-gost/gost v3.3.1` & `3x-ui`)**：GOST 链式代理与 3x-ui 可视化面板方案。
4. **来源 D (`Google IAP TCP Forwarding` 官方文档)**：IAP 无公网 IP 访问与 IAM 最小权限规范。

## 2. 逐项对照矩阵 (已采用 vs 未采用 vs 差距补救)

| 领域 | 公开方案最佳实践 | 现行部署状态 | 差距诊断 | 补救动作 (本实验场产出) |
|---|---|---|---|---|
| **流量防账单** | `gcp-free-tier-proxy` 的 `egress-guard` 脚本 (硬顶熔断 + systemd timer) | ❌ **未配置** (无防护裸奔) | 存在黑客扫频或死循环流量导致高额账单风险 | **已落地**：编写 `egress-guard.sh` + systemd 单元 (`01_GCP egress防护.md`) |
| **SSH 管理面加固** | Google IAP TCP Forwarding (关闭 0.0.0.0/0 22 端口，仅允许 IAP CIDR) | ❌ **未配置** (22 端口全网开放) | 暴露在全网 SSH 暴力破解扫描下 | **已落地**：给出 IAP 防火墙与 SSH 迁移配置 (`09_GCP网络架构加固.md`) |
| **代理协议选型** | sing-box VLESS-Reality TCP 443 + 真实 TLS 证书伪装 | ✅ **已采用** (`www.snapchat.com`) | 完全符合官方规范与最高抗封锁级别 | **保持现状**：评价与选型报告 (`07_Reality伪装站选型评估.md`) |
| **客户端 TUN IPv6** | sing-box TUN 配置 `inet6_address` (ULA) + `::/0` 接管 | ❌ **配置缺失** (仅 IPv4 路由) | LAN 侧 PC 的 IPv6 流量不通 | **已落地**：给出 TUN IPv6 补丁 (`02_PC IPv6修复与路由对比.md`) |
| **晚高峰 QoS 优化** | Linux BBR 拥塞控制 + sing-box Multiplexing (h2mux) | 🟡 **部分采用** (仅 TCP 443，未显式开启 Mux) | 晚高峰 HTTP/2 小包握手延迟偏高 | **已落地**：给出晚高峰调优决策树与 Mux 补丁 (`03_晚高峰调优.md`) |
| **流量可视化** | 不暴露公网 Web 面板，仅走 Localhost REST API 或 CLI | 🟢 **保持裸机无面板** | 现行无面板但极度安全；避免了 3x-ui 历史 RCE 漏洞 | **已落地**：推荐 sing-box REST API + SSH 隧道方案 (`05_流量监控方案评估.md`) |
| **主备自动故障转移** | sing-box `urltest` 自动健康检查与组切备 | ❌ **未配置** (仅死板单节点) | 遇到 Rola 出口宕机或 Reality 阻塞时无法自愈 | **已落地**：给出 `urltest` 自动切备补丁 (`08_主备自动切换.md`) |

## 3. 总结与改进路线图

通过与公开社区作业深度对照，我们成功识别并补齐了现行部署中的 **5 大核心短板**：
1. 补齐了 **GCP egress 账单硬防护** (`egress-guard`)。
2. 补齐了 **IAP TCP Forwarding 零信任 SSH 管理**。
3. 补齐了 **LAN PC 全屋 IPv6 透明接管配置**。
4. 补齐了 **sing-box `urltest` 多协议自动故障转移**。
5. 补齐了 **不增加攻击面的轻量流量监控方案**。
