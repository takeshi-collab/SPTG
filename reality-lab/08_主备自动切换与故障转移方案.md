# 08. 主备自动切换与故障转移方案设计

**状态**：结论明确，附 sing-box `urltest` 自动故障转移配置补丁

---

## 1. 现状与需求分析

- **现状**：Hub 上同时运行 VLESS-Reality (443)、Hysteria2 (UDP 443) 和 WireGuard (UDP 51820) 三套服务。但 OpenWrt 客户端当前仅硬编码连接 VLESS-Reality。
- **痛点**：若 VLESS-Reality 链路被老挝 5G 高峰期丢包打垮、或出口 A (Rola IPv4) 宕机，客户端无法自动切换至 Hysteria2 或 WireGuard 备用隧道，导致全屋断网。
- **目标**：在 OpenWrt 客户端配置 sing-box 原生 `urltest` 自动探测与故障转移机制，实现**主链路故障秒级无感切备，主链路恢复自动切回**。

---

## 2. sing-box 原生 `urltest` 自动切换方案 (推荐)

`sing-box` 提供了 `urltest` 出口组 (Outbound Group)，会定期向指定 URL (如 `https://www.gstatic.com/generate_204`) 发起 HTTP Ping，自动选择延迟最低且可达的节点。

### 2.1 客户端 `config.json` 自动故障转移补丁

```json
{
  "outbounds": [
    {
      "type": "urltest",
      "tag": "auto-outbound",
      "outbounds": [
        "vless-reality-main",
        "hysteria2-backup",
        "wireguard-backup"
      ],
      "url": "https://www.gstatic.com/generate_204",
      "interval": "30s",
      "tolerance": 50,
      "idle_timeout": "30m"
    },
    {
      "type": "vless",
      "tag": "vless-reality-main",
      "server": "<HUB_IP>",
      "server_port": 443,
      "uuid": "<USER_UUID>",
      "flow": "xtls-rprx-vision",
      "tls": {
        "enabled": true,
        "server_name": "www.snapchat.com",
        "reality": {
          "enabled": true,
          "public_key": "<REALITY_PUBLIC_KEY>",
          "short_id": "<REALITY_SHORT_ID>"
        }
      }
    },
    {
      "type": "hysteria2",
      "tag": "hysteria2-backup",
      "server": "<HUB_IP>",
      "server_port": 443,
      "password": "<HY2_PASSWORD>",
      "tls": {
        "enabled": true,
        "server_name": "<HUB_DOMAIN>",
        "insecure": true
      }
    },
    {
      "type": "wireguard",
      "tag": "wireguard-backup",
      "server": "<HUB_IP>",
      "server_port": 51820,
      "local_address": ["10.0.0.2/32"],
      "private_key": "<CLIENT_WG_PRIVATE_KEY>",
      "peer_public_key": "<HUB_WG_PUBLIC_KEY>"
    }
  ],
  "route": {
    "rules": [
      {
        "outbound": "auto-outbound"
      }
    ]
  }
}
```

---

## 3. 探活参数与切备逻辑

1. **探测间隔 (`interval: "30s"`)**：每 30 秒后台探测一次 204 状态码，开销极低。
2. **容忍延迟 (`tolerance: 50`)**：仅当备用节点延迟比主节点低 50ms 以上时才发生切换，**防止因网络微小抖动频繁切节点**。
3. **主备优先级排序**：`urltest` 列表第一位的 `vless-reality-main` 默认为高优先级主节点。

---

## 4. 本地验证与故障演练步骤 (验证方法)

本地执行体在应用补丁后，可通过以下方式演练故障转移：

1. **模拟主节点故障**：
   在 GCP Hub 上临时阻断 Reality 443 端口：
   ```bash
   sudo iptables -A INPUT -p tcp --dport 443 -j DROP
   ```
2. **观察 OpenWrt 客户端日志**：
   ```bash
   logread -e sing-box
   ```
   **预期日志**：显示 `[URLTest] vless-reality-main is offline, switching to hysteria2-backup`。
3. **验证全屋代理连通性**：
   LAN 侧 PC 访问 `https://google.com` 依然正常打开。
4. **恢复主节点**：
   ```bash
   sudo iptables -D INPUT -p tcp --dport 443 -j DROP
   ```
   **预期日志**：显示 `[URLTest] vless-reality-main is back online, restoring primary outbound`。
