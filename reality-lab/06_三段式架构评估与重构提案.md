## 1. 当前“三段式”架构推演

### 1.1 拓扑结构
```
[LAN 设备 (PC/手机)]
       │
       ▼ (透明代理 TUN)
[老挝 5G CPE (OpenWrt / ImmortalWrt Router)]
       │
       ▼ (第一段：VLESS-Reality TCP 443 / 伪装站 www.snapchat.com)
[GCP Hub (usa-hub-1 @ us-west1-a)]
       │
       ▼ (第二段：双静态 SOCKS5 出口)
 ┌─────┴────────────────────────┐
 ▼ (出口 A: 住宅 IPv4, 限速 10M)  ▼ (出口 B: 静态 IPv6, 不限速)
[Rola IPv4 Gateway]           [Rola IPv6 Gateway]
       │                              │
       └──────────────┬───────────────┘
                      ▼ (第三段：目标互联网)
          [Global Internet / AI APIs]
```

### 1.2 架构设计初衷与优缺点

- **优势**：
  1. **强抗封锁**：老挝 5G CPE 到 GCP Hub 采用 VLESS-Reality 协议，TLS 1.3 + 真实 Snap Inc. 证书伪装，抗 GFW / 运营商 active probing 能力最强。
  2. **高干净度 (IP Reputation)**：最终落脚点为 Rola 住宅 IP，绕过 Cloudflare 人机验证与 Google / AI API (OpenAI/Claude) 的机房 IP 封禁。
  3. **整屋无感**：OpenWrt TUN 接管全屋流量。

- **隐患与痛点**：
  1. **链路冗长 (Three-Hop Overhead)**：数据包经过两次代理转发（CPE ➔ Hub ➔ SOCKS5 Exits），增加 20ms~50ms 转发延迟与 CPU 序列化开销。
  2. **出口 A 10M 带宽瓶颈**：全屋默认流量经出口 A 被严重限速。
  3. **依赖 SOCKS5 出口供应商稳定性**：若 Rola 节点故障，整链中断。

## 2. 替代架构对比矩阵 (稳 / 快 / 省 / 抗封 / 复杂度)

| 架构方案 | 稳定性 | 速度/延迟 | 成本 | 抗封锁能力 | 部署复杂度 | 适用场景 |
|---|---|---|---|---|---|---|
| **方案 0：现行三段式**<br>`CPE TUN ➔ GCP Reality ➔ SOCKS5 A/B` | 🟢 高 | 🟡 中 (三段开销，出口 A 10M 限速) | 🟡 中 (GCP + Rola 月费) | 🟢 **极高** (TLS 1.3 Reality + 住宅 IP) | 🟡 中 | **个人 AI 开发、账号风控敏感场景 (现状最优解)** |
| **方案 1：两段式直连 (UDP)**<br>`CPE TUN ➔ GCP Hysteria2 / TUIC` | 🟡 中 (晚高峰 UDP 易被 QoS) | 🟢 **极快** (QUIC 拥塞控制，无 SOCKS5 转发) | 🟢 **更省** (省去 SOCKS5 出口费用) | 🟡 中 (UDP 443 特征易被老挝 5G 限速) | 🟢 低 | 适合大文件下载、高码率视频，抗 QoS 能力较弱 |
| **方案 2：GOST 中转链**<br>`CPE ➔ 国内/跨国 Relay ➔ GCP Reality` | 🟢 高 | 🟡 中 (两跳 RTT 累加) | 🔴 贵 (需额外中转机) | 🟢 高 | 🔴 复杂 | 仅当老挝到 GCP 直连线路严重恶化时引入 |
| **方案 3：Cloudflare CDN 前置**<br>`CPE ➔ Cloudflare Edge ➔ GCP` | 🟡 中 | 🔴 较慢 (WebSocket / gRPC 开销) | 🟢 免费/低成本 | 🟢 高 | 🟡 中 | 适合 GCP IP 被墙后的应急救砖方案 |
| **方案 4：WireGuard 纯 Mesh**<br>`CPE ➔ GCP WG 隧道` | 🟢 高 | 🟢 快 | 🟢 省 | 🔴 **低** (无 TLS 伪装，老挝 5G 易直接封 UDP 51820) | 🟢 低 | 内网互联，不适合翻墙出海 |

## 3. 架构优化与重构提案

### 结论与决策：
1. **维持现状“三段式”主骨架不动**：对于“AI 开发 + 风控敏感账号”核心诉求，VLESS-Reality + 静态住宅 IP 仍是当前综合安全度和可用性最高组合。推翻现状改用纯直连会丧失住宅 IP 保护。
2. **重构第二段出口分流（“2.5 段式”按需分流）**：
   - **分流 A (敏感/风控)**：OpenAI, Anthropic, Google Account, Stripe ➔ 走出口 A (Rola 住宅 IPv4)。
   - **分流 B (大流量/普通)**：YouTube, GitHub, Docker, HuggingFace, Steam ➔ **直连 GCP Hub 出口或走 IPv6 出口 B**，绕过 10M 限制，吞吐提升 10 倍。
